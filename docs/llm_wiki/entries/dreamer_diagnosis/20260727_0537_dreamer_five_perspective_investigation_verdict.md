# 5-perspective Dreamer investigation: clean implementation, wrong size, inverted rr premise

## Key conclusion

A five-agent parallel investigation (speed / code faithfulness / curves / settings regime / task difficulty) of the in-house DreamerV3 (`dreamer_srl`) concluded: the implementation is line-faithful to sheeprl (0 red findings; free-nats clamping and truncated-vs-terminated handling verified correct on request); learning is healthy per unit experience (beats rPPO 2.4x survival at matched 170k episodes, still improving) but ~100x slower in wall-clock — structurally, not fixably; XS (3.17M params) matches M (20.7M) at matched episodes, so M is oversized (paper's only vector benchmark uses its smallest net at its highest update rate — we ran the opposite corner); the earlier "replay ratio 0.0625 is 16x too low" premise was WRONG (paper's big-budget runs use train_ratio 32 vs our 64; but the budget-matched interpolation for our ~30-50M-step regime is ~100, and the wall-clock frontier says rr 0.25 is wall-clock-POSITIVE, α≈0.66-0.78 vs break-even 0.27-0.35); ~2x wall-clock is recoverable (34-44% of time is checkpoint/video stalls; the acting path is un-jitted, 436 eager dispatches/iter; Python autoreset ~22ms/iter). The convergent finding across three independent methods: the binding constraint is the VALUE PATHWAY around rare lethal events, not the world model (which plateaued), not capacity, not the port.

## Evidence, measurements, facts

- Faithfulness: 0 red / 5 yellow / 6 green (docs/reviews/dreamer_srl_faithfulness_review.md); D-015 quantization verified benign at 128 and 16 envs.
- Curves: WM loss -0.7% over last 8M steps (plateaued) while survival 48→123 monotone; value MAE still -20%; only moving WM error = negative-reward MAE (-19%).

- Replays-per-parameter: M ρ≈62, XS ρ≈400-600 vs paper's 4-16 — nobody is under-updated.
