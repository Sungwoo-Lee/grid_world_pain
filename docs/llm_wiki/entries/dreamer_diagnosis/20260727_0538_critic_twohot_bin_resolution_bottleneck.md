# Critic two-hot bin resolution: 1 bin ≈ 52 survival-steps; the whole task fits in ~10 of 255 bins

## Key conclusion

DreamerV3's critic and reward heads express values as a categorical distribution over 255 bins evenly spaced in SYMLOG space over ±20 — a general-purpose ruler covering ±485M that backfires on our task: our controllable value range (≈ −100·0.997^{steps-to-death}, from "die now" −100 to "survive the 500 cap" −22) occupies bins ~98–107, i.e. ~10 bins. Because value decays exponentially in survival time and bins are log-spaced, the two cancel to a clean constant: ONE BIN ≈ 52 SURVIVAL-STEPS (at ±6: ~16). All learning to date (survival 52→120) = 1.2 bins; a 10-vs-20-steps-to-predator distinction = 0.18 bins. Sub-bin values ARE representable (expected-value readout is continuous) — the issue is signal-to-noise: cross-entropy gradients for sub-bin distinctions are tiny vs. minibatch/mixture noise. Uniform reward rescaling is a NO-OP (symlog resolution is scale-relative); the fix is narrowing the RANGE. ±6 covers ±402 vs a computed worst-case target ≈ −270 (sustained ~−0.5/step over the 333-step horizon + death) — the smallest integer range with real margin; ±5 (±147) would clip.

## Evidence, measurements, facts

- Grid: linspace(low, high, 255) in symlog space, built per-call in src/algorithms/dreamer_srl/loss.py (TwoHotEncodingDistribution, defaults −20/20 = sheeprl parity); NOT a learned parameter, so old checkpoints load mechanically but are semantically scrambled across ranges.
- Bin table for our env (γ=0.997): bin 98=−95 ("death ~16 steps"), 99=−81 (~69), 100=−69 (~122, current skill), ..., 107=−22 (~497 ≈ cap). Bins 0–97 and 108–254 unreachable.
- H2b independently found the only still-moving WM error is negative-reward MAE and value MAE lags — consistent with a critic at its resolution floor.
