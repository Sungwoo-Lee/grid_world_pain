# Agent model tiering — critique on Fable, doing on Opus, no Sonnet

## Key conclusion

The agent team now splits on a simple rule: **critique and domain theory run on Fable; orchestration, building, running, and literature extraction run on Opus.** Sonnet is no longer used by any agent. The mechanism worth remembering is that `model: opus` / `model: fable` in a profile's frontmatter is an **alias for a tier**, not a pinned release — it floats to whatever the newest model in that family is, so a model launch changes every agent's behaviour without any file changing. Pinning requires writing a full model ID.

## Evidence, measurements, facts

- Final assignment, verified by reading every profile's `model:` line: **Fable (10)** — the four reviewers (`code-reviewer`, `math-reviewer`, `plan-reviewer`, `env-config-reviewer`) plus the six professors (`bayesian-brain`, `pain-modeling`, `rl`, `bayesian-nn`, `dl-theory`, `neuromodulation`). **Opus (11)** — `agent-manager`, `pi`, `senior-developer`, `developer`, `experiment-designer`, `experiment-analyzer`, `training-runner`, `bug-curator`, `research-postdoc`, `literature-reviewer`, `literature-curator`.
- Previously Sonnet-backed and promoted to Opus: `developer`, `env-config-reviewer` (then still `env-config-auditor`), `bug-curator`, `training-runner`. `developer` and `training-runner` are the highest-volume agents, so this is where the cost shifted most.
- Frontmatter is the authority; the session's own `/model` setting does not propagate to sub-agents, and sub-agent frontmatter does not follow the session. `model: inherit` is the opt-in for tracking the parent.
- Unverified: whether a bare `opus` alias in a sub-agent inherits the parent session's 1M-context variant or the standard-context build. Matters for context-heavy agents like `literature-reviewer`.
- Fable output quality on review work was checked against a real artefact, not asserted: the `plan-reviewer` run on the async-render plan verified every code citation in the plan and produced 7 findings with owners.

## Decisions and actions

- One rule to remember instead of 21 assignments: reviewing and theorising on Fable, doing on Opus.
- `env-config-auditor` was renamed `env-config-reviewer` in the same pass — it was already a reviewer in everything but name (writes only to `docs/reviews/`, same severity scale, modifies nothing).
- Rename discipline for a team-wide identifier: instructional references were updated (agent profiles, `CLAUDE.md`, playbook, config guides, live configs, KNOWN_BUGS — 35 tokens), while historical records under `docs/reviews/`, `docs/experiments/`, `docs/llm_wiki/`, `docs/diary/` and `configs/**/archive/` keep the old name, because renaming those would make past reports claim an agent that did not exist yet.

## Open questions and follow-ups

- Two professors (`dl-theory`, `bayesian-nn`) have barely been used since the bench was split; consolidation is a research-needs judgement the user has not made.
- `research-postdoc` and the two literature agents sit in the researchers table but stay on Opus, which is a deliberate asymmetry (triage and extraction, not critique) and may look inconsistent later.
