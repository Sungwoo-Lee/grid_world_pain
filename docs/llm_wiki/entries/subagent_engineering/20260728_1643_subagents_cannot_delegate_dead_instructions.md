# Sub-agents cannot delegate — "consult `<other-agent>`" is a dead instruction

## Key conclusion

A sub-agent can only use the tools listed in its own `tools:` frontmatter. Across the 21-agent team, exactly one profile — `senior-developer` — carries the `Agent` tool. Every other profile that instructed its agent to "consult `bug-curator`" was therefore asking for something structurally impossible. The instruction did not error; it silently degraded into whatever the agent decided to do instead. Any cross-agent consultation written into a profile must be re-expressed as either (a) a direct file read the agent can actually perform, or (b) something the **parent** does before spawning.

## Evidence, measurements, facts

- Tool audit: `grep -l '^tools:.*Agent' .claude/agents/*.md` returns exactly one file, `senior-developer.md`.
- Four profiles carried the dead instruction: `developer`, `plan-reviewer`, `code-reviewer`, `env-config-reviewer`. Two of those (`code-reviewer`, `env-config-reviewer`) had it introduced *the same day* by a single-sourcing edit that replaced their inline latent-bug lists with "query `bug-curator`" — removing working knowledge and pointing at an unreachable door.
- The detection came from real output, not from reading the profiles: a `plan-reviewer` run by a parallel session on the async-render plan wrote "**Prior-art / known-bug check** (targeted grep of the registry, in lieu of a `bug-curator` spawn)". The agent compensated correctly and said so; a less careful run would simply have skipped the prior-art pass.
- Fix shipped in `87a2e4d`: the four profiles now say to run `grep -i '<area>' docs/develop/active/issues/KNOWN_BUGS.md` themselves (all four hold `Grep`), name `bug-curator` as owner of anything ambiguous, and never report a prior-art pass as done if it was skipped. `bug-curator` gained a "How You Get Invoked" section stating that serve mode is parent-mediated.

## Decisions and actions

- Cross-agent consultation in a profile is only valid if that profile holds `Agent`. Otherwise write the file-read the agent can do, and let the parent pre-fetch anything richer.
- Auditing an agent system against **its own real output** found this in one read; auditing the profiles against each other had not. Prefer reading what agents actually produced.
- Follow-up: no other profile currently instructs a cross-agent spawn, but any new profile must be checked against its own `tools:` line.

## Open questions and follow-ups

- `agent-manager` has the lowest doc footprint of the whole team (~25 mentions vs ~1000 for `senior-developer`), so the routing layer it owns may rarely execute. Unmeasured: how often the manager is actually spawned versus bypassed.
