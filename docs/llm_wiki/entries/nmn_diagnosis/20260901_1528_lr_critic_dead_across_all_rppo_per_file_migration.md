# The dead lr_critic is not NMN-specific, and its migration has a per-file trap

## Key conclusion
`lr_critic` is declared in 23 YAML files and read by **no Python anywhere**. Every recurrent
PPO run in project history — plain baselines included, not just NMN — has trained its critic
at `lr_actor`. When wiring it up, each file's critic and modulator must inherit **that file's
own** `lr_actor`; a single blanket value silently changes plain PPO.

## Evidence, measurements, facts
- `grep -rn lr_critic src/ train.py scripts/` returns **nothing**. Only 23 YAMLs declare it.
- `train.py:762` — `lr = args.lr or config.get_mandatory('agent.lr_actor')`.
- `train.py:1165-1172` — the rPPO branch builds **one** `nnx.Optimizer` with a single Adam
  over `wrt=nnx.Param`: trunk, actor head, critic head and modulator all ride it.
- Plain PPO is affected identically: `src/models/ppo_trainer.py` reads no learning rate, and
  `train.py:1259` carries the comment "For now, let's use lr_actor as primary".
- **The trap**: `configs/models/ppo/ppo.yaml` has `lr_actor: 0.0003` / `lr_critic: 0.001` —
  its declared critic rate is HIGHER than its actor rate, the reverse of the rPPO case. A
  blanket 0.0005 migration would have changed its critic from the 0.0003 it actually uses,
  introducing the exact behaviour change the migration exists to prevent.
- 20 rPPO files are 0.0005/0.0001; `neuromodulated_ppo.yaml` is 0.0005/0.0001;
  `ppo.yaml` is the sole outlier.
- Also dead: `percept_bias_init` is **ignored whenever type is FiLM** — the code hardcodes the
  gamma bias to 1.0 for identity (`neuromodulator.py:91-95`) and only sigmoid-style modulation
  reads the declared value. Same pattern, second instance.

## Decisions and actions
- User decision: **wire it, do not remove it** — "if the critic lr is not defined at all, we
  need to define". Values follow current actual behaviour, so training dynamics are unchanged.
- A new `lr_modulator` key is added so the modulator's training speed is a controlled variable
  rather than an accident of which optimizer it joined — it is the object of study.
- Optimizer design: one shared Adam with a per-leaf learning-rate multiply, on the identity
  `optax.adam(lr) == chain(scale_by_adam(), scale(-lr))` — **verified** by the plan-reviewer,
  which ran 10 update steps of old vs new and got bitwise-identical parameters.
  `optax.multi_transform` was rejected: it would silently convert the global gradient clip
  into a per-group clip.
- `configs/environment/experiment/archive/hypervigilance/testbed_cellC_native_v2.yaml` is
  deliberately NOT migrated — it is an auto-dumped historical snapshot; editing it would
  rewrite a record.

## Open questions and follow-ups
- Because all three rates are equal today, the bit-identity test **cannot** detect a mislabelled
  parameter group. The escape is deliberately-unequal-rate tests that zero one group and observe
  which parameters actually moved.
- Naming trap for the labeller: `mod_unimodal_ln` / `mod_multimodal_ln` / `mod_flat_ln`
  begin with "mod" but are task-side encoder LayerNorms and must be labelled **trunk**.
