# Unquoted YAML frontmatter dates parse as datetime.date and break string-keyed sorts

## Key conclusion
`scripts/regen_dev_index.py` crashed for every session with `TypeError: '<' not supported between instances
of 'str' and 'datetime.date'`, blocking `docs/develop/INDEX.md` regeneration. Root cause: **unquoted YAML
dates** like `created: 2026-06-22` are parsed by PyYAML as **`datetime.date` objects**, not strings — and the
script's sort key mixed those real date objects with a `""` fallback for docs missing `last_updated`, so it
tried to compare `str < datetime.date`. Fix: **coerce the sort key to `str(...)`** (ISO-format dates still
sort chronologically as strings).

## Evidence, measurements, facts
- `scripts/regen_dev_index.py:124,145`: `key=lambda x: x[1].get("last_updated", "")` -> mixed `date` and `""`.
- Fix (commit `e8a3489`): `key=lambda x: str(x[1].get("last_updated", ""))` at both sort sites. Script then
  ran clean and regenerated `INDEX.md` (134 docs).

## Decisions and actions
- Generalizable: any string-keyed sort/compare over YAML frontmatter dates must **`str()`-coerce (or quote the
  dates)** — this project uses unquoted dates widely, so the trap can recur in other doc-tooling scripts.
