# terminate_command.py: SSH key auth + --yes flag (parity with run_command.py)

## Key conclusion
Before this refactor, `terminate_command.py` could not be invoked by the agent harness because it used `pexpect.spawn` + `getpass.getpass` to authenticate over SSH (interactive password prompt, no way to provide a password from a non-interactive Bash tool call). The fix: replace pexpect with `subprocess.run` and pass the same SSH options that `run_command.py` uses (`BatchMode=yes`, `ControlMaster=auto`, `ControlPath`, `ConnectTimeout=5`). SSH keys are already configured on the lab nodes for `vncuser@192.168.0.10X`. Also added `--yes` for non-interactive confirmation; kept the two-stage scan/confirm/kill flow as default so the agent and the user can both still see what would be killed before it happens.

## Evidence, measurements, facts
- Pre-refactor code at `terminate_command.py:85-103` used `pexpect.spawn(ssh_cmd, encoding='utf-8', timeout=timeout)` and `getpass.getpass(...)` to read a password.
- run_command.py (already working with SSH keys) uses `subprocess.run(["ssh", "-o", "BatchMode=yes", "-o", "ConnectTimeout=5", "-p", "1800", ...])` — this is the pattern the refactor mirrors.
- The refactored `ssh_execute()` at `terminate_command.py:83-110` adds `ControlMaster=auto` + `ControlPath=/tmp/ssh_mux_term_<ip>_<port>_<user>` + `ControlPersist=60` so parallel scan/kill calls (via `ThreadPoolExecutor`) reuse a single SSH connection per node.
- Added `-y/--yes` flag at line 154; gated the `(y/N)` prompt at line 210 so non-interactive use just prints "skipping confirmation" and proceeds.
- Tested live on 2026-05-07: `echo "n" | ./terminate_command.py 114 dreamer_ablation_lever_only_s0` listed PIDs and aborted cleanly; `./terminate_command.py 114 <tag> --yes` killed processes via SIGINT; the `terminate_command.py 114 <tag> -f -y` escalation path also tested.

## Decisions and actions
- Refactor landed in commit `40f0f4d`. Trade-off: lost the password-auth fallback for any edge case where SSH keys aren't configured, but the lab cluster's SSH keys are already required by `run_command.py`, so any node where `run_command.py` works will also work with `terminate_command.py` after this change.
- Added `--yes` flag rather than removing the confirmation prompt entirely — keeps the safety net for human users while unblocking agent automation.
- Updated training-runner profile §4c to document the new direct-invocation capability (commit `fcdf1cc`).
- Added matching feedback entry in built-in MEMORY.md so future runners know they can call it directly.

## Open questions and follow-ups
- The `BatchMode=yes` option will fail-fast on missing keys instead of prompting. This is correct for the agent path but means the bootstrap step (`scripts/bootstrap_lab_ssh.sh`) is a hard prerequisite. Documented in the runner profile's "Setup Preconditions" section.
- Should `run_command.py` also gain a `--yes` flag (it has no confirmation prompt today; this is a parallelism question, not a behavioral change)? Not urgent.
