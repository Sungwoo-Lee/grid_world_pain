# log_interval anchored to rows-per-session, not env-steps-per-row

## Key conclusion

`log_interval` is most usefully chosen so a typical session writes ~100–200 WandB rows (good for eyeballing curves without scrolling). Anchoring to env-steps directly mis-scales across algorithms with very different episode-completion rates. The 4 prior `_log50k` dreamer-srl cells (oxm78on8 / 50cpronf / 2r5hc0oz / hbqje3dt, launched 2026-05-28) used `log_interval=50000` — copied from the env-step cadence of rPPO production runs — and produced only 4–6 rows over the entire session, making trajectory-shape unreadable. Recomputing from rows-per-session: rPPO production reaches ~10M episodes / 24h with `log_interval=50` (~2500 rows); dreamer-srl reaches ~20–40k episodes / 24h (250–500× less), so to match the same row-density target it needs `log_interval` lowered by the same factor — landing at ~2000 for dreamer-srl @ ~38 SPS / num_envs=16.

## Evidence, measurements, facts

- rPPO production reference: ~10M episodes / 24h with `log_interval=50` → ~2500 WandB rows/session.
- Dreamer-srl @ ~38 SPS / num_envs=16 → ~0.08 episodes finish per iteration steady-state → ~20–40k episodes / 24h.
- Pre-fix `log_interval=50000` cells: ~800k env-steps per row, ~4–6 rows/22k-episode session — empirically useless for curve inspection.
- Post-fix `log_interval=2000`: ~160 episodes per row, ~140 rows in a 22k-episode session — same row-shape resolution rPPO has at production scale.
- Read-priority order in dreamer_srl_main.py: `--log-interval` CLI > YAML `training.log_interval` > env_cfg default (10).
- 4 in-flight `_log2k` post-fix cells launched 2026-05-29 02:09 KST: w9as1qe3 (s42, n114:0), x0ahp61j (s43, n114:1), jx3obafg (s44, n113:0), h7aa37na (s45, n113:1).
- Fix landed at `configs/models/dreamer_srl/01_food_only_buf256k.yaml:134` (with rationale comment). Commit `0de7fe4`.

## Decisions and actions

- New rule of thumb: choose `log_interval` so a 24h session produces ~100–200 rows, given the algorithm's empirical iteration→episode conversion rate.
- For dreamer-srl @ XS / num_envs=16: `log_interval=2000`. For rPPO at production: `log_interval=50` (existing).
- The new YAML carries a comment with the rationale + the 4 prior crash run IDs as the evidence trail (so future me / parallel sessions don't re-copy the rPPO number).
- Open: empirical verification of the 140-row count once one of the 4 in-flight cells completes a full 24h session.

## Open questions and follow-ups

- Once first `_log2k` cell hits ~12h, verify the row count is in the ~70–100 range (half of full session) — confirms the 2000 figure.
- If parallel-env scaling lands (e.g., num_envs raised to 32 or 64), `log_interval` will need to scale up proportionally — the rule (~140 rows/session) is invariant; the number that achieves it is not.
