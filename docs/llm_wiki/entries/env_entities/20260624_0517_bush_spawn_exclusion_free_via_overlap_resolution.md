# Animal spawn-exclusion from bushes is already free (overlap resolution gives unique cells)

## Key conclusion
The intended Phase-2 feature — stop animals from **spawning** on bush cells — required **no code and zero
added reset time**, because the existing placement step **`resolve_overlaps_global`** assigns every entity a
**unique cell**. Bushes are entities in that resolution, so an animal can never share a cell with a bush at
spawn. A cheap empirical probe confirmed it before any implementation, avoiding the reset-cost regression
the user was worried about.

## Evidence, measurements, facts
- `core.py:747 resolve_overlaps_global`: a `lax.scan` over all entities (res, pred, obs, neutral) with a
  shared flat occupancy mask; any entity whose cell is taken is relocated to a free cell -> all-unique.
- Probe (2000 vmapped resets of the whole-grid `default.yaml`, count-ranges + bushes): **0 active-animal-on-
  active-bush co-locations; 0/2000 resets** had any.
- Caveat: holds for **non-pathological densities** (default ~3 animals + ~10 bushes on 100 cells). If a config
  packed entity count near the cell count, resolution could run out of free cells and overlaps reappear.

## Decisions and actions
- **Do NOT implement spawn-exclusion** — already guaranteed. The "perfect bush refuge" is complete with
  Phase-1 movement-exclusion ([[20260624_0516_bush_blocks_animals_movement_toggle]]) + the existing
  overlap resolution.
- Methodology: a sub-second empirical probe before building settled the decision — same "measure before you
  commit" spirit as [[20260623_0145_proxy_benchmark_contention_misestimate]].
