# Inactive resource slots revived on step 1 — mask must cover the respawn path

## Key conclusion
When you add a per-episode "active" mask, it must be threaded through **every** consumption site —
**including respawn/regeneration**, not just sensing/movement/damage. The blocker: `update_resources`
overloaded `res_active == False` to mean "eaten, now regrowing", so a never-allocated (off count-range)
food/hiding_predator slot satisfied the respawn condition and **turned on after a single `jax_step`** —
every episode collapsed to max resource count, silently nullifying the variance the feature was built to
add. The new animal/obstacle masks were complete; only the **resource** family — assumed "no change
needed because it already has `res_active`" — carried the overloaded-semantics trap.

## Evidence, measurements, facts
- `src/environment/core.py` `update_resources`: `respawn_mask = ~res_active & (new_reg_timer <= 0)`.
  A never-activated slot starts with `res_active=False`, `reg_timer=0` -> `True` -> re-placed on grid.
- Reproduced: a reset drawing K=1/4 active food (3 parked) became **4/4 active after one step**.
- Found INDEPENDENTLY by both `senior-developer` (verification) and `code-reviewer` -> CHANGES-REQUESTED.
  The animal_active / obs_active masks were verified complete at every site.
- A test gap hid it: `test_mask_stable_within_episode` checked only animal/obstacle mask stability and
  used no resource range, so `res_active` was never stepped-and-checked.
- Fix (`61e0c73`): new immutable `EnvState.res_allocated` (set once at `jax_reset` from the reset
  activation mask, never mutated by step) gates respawn: `respawn_mask &= res_allocated`. Test extended
  to assert `sum(res_active) <= reset K` across the episode — fails pre-fix, passes post-fix.

## Decisions and actions
- Shipped the `res_allocated` fix + the strengthened test + regenerated the 2 default fixtures.
- Generalizable lessons: (a) a boolean flag reused for two meanings (allocated vs alive) is a trap —
  separate them; (b) mask-completeness must include respawn/regeneration paths; (c) "this family needs no
  change because it already has a mask" is exactly where the bug hid; (d) parity didn't catch it because
  the default was the only ranged config and its fixture was regenerated.
