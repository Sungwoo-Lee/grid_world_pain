# Removing a YAML list entry needs a full restatement - and a runtime test, not a config read

## Key conclusion
Two lessons from building the no-hiding-predator replicate. (1) The `extends:` system deep-merges MAPPINGS but REPLACES LISTS, so there is no way to "delete" one entry of `environment.resources` by overriding - the child must restate the entire list containing only what should remain. (2) A config that *reads* correct is not a config that *behaves* correct: the user asked whether the change actually worked under the hierarchical config system, and the decisive check was constructing both environments and comparing runtime state, which also surfaced the comparability question (does dropping a resource shift the observation layout?) that config inspection cannot answer.

## Evidence, measurements, facts
- The parent config carries `hiding_predator` as a RESOURCE (not an obstacle/entity - it sits in `environment.resources`, easy to look for in the wrong list), count 2-12, damage 15-45, nociception 0.9; the source comment reads "ALL-COMBINED: more ambush predators, running is risky".
- The child restates `environment.resources` with the food block only. Verified three ways, escalating in authority: (a) source-side `load_env_config` resolution, (b) the SAVED `models/config.yaml` of the actually-running job, (c) the running job's own startup audit line `resources : 1 items (food)`.
- RUNTIME TEST (built both envs, reset, random-walk episodes):
  - per-slot resource damage: parent `[(0,0)x4, (15,45)x12]` -> no-hide `[(0,0)x4]` (12 harmful slots -> 0)
  - **obs_dim 27 in BOTH**, identical breakdown (Satiation 1, Intero-Nocicept 1, Extero-Nocicept 1, Olfaction 5, Collision 5, Proprioception 6, Visual 8). Removing a resource TYPE cannot shift the observation layout because `sense_resource` reduces `[num_res, vector_size] -> [vector_size]`; channels are fixed-width. This is what preserves comparability with the parent sweep.
  - random-walk damage: 1072 (parent) vs 394 (no-hide) over 12 episodes. The residual is expected and intended - the hunting predator (damage 15-120, plus pounce) and rocks (1-5) remain, since the threat that motivates hiding must stay or the experiment is meaningless. Mean damage per event drops ~31 -> ~14.
- Agent-config drift was checked at the same time (a bigger comparability risk than the resource change): parent and replicate both resolve to `encoding_mode: hierarchical`, hidden 128, gamma 0.95, MC returns, and `recurrent_ppo.yaml` has no git changes since the parent launch.

## Decisions and actions
- Shipped 10 no-hiding-predator arm configs (`cfc0293`), each a 1-key-list restatement over its parent rest-premium arm; probe sweep spec `d0da3ce`.
- Practice reinforced: for any "I removed X from the env" change, run the env and compare state/obs, do not stop at reading the resolved config.
