# experiment-eval opt-in moved to a config-layer --eval-config selector

## Key conclusion
The "run behavior probes at every checkpoint during training" opt-in was moved from a `--experiment-eval` CLI flag (+ `training.experiment_eval_*` keys) to a **config-layer selector**: `train.py --eval-config <path>`, defaulting to `configs/evaluation/default.yaml` (feature OFF), with an opt-in preset `configs/evaluation/experiment_on.yaml` that `extends: evaluation/default` and sets only `experiment.during_training.enabled: true`. `train.py` loads it via the extends-resolving loader and merges it, so the preset inherits all sibling fields. This makes the run's setting saved/reproducible in its config rather than living in a launch flag.

## Evidence, measurements, facts
- Two design principles applied: (1) **config selector vs behavioral flag** — `--eval-config` behaves like `--config` (points at a config file whose `extends:` is resolved), not a boolean toggle; (2) **self-documenting defaults** — the default config lists EVERY field with inline notes (valid option names, defaults) so a reader sees the full option surface; inherited presets pick per-purpose values.
- The gate reads `config.get_mandatory('experiment.during_training.enabled')` after the eval config is merged (top-level `experiment.*`, not `evaluation.experiment.*`, because the file's top key is `experiment:`).
- Verified: default run -> enabled False, no dispatch, no `Experiment/*` WandB series; `--eval-config experiment_on.yaml` -> checkpoint dispatch + `Experiment/bush_dwell` logged. Both complete cleanly (A/B smoke).
- Scoped to rPPO only (Dreamer trainer integration handled separately).

## Decisions and actions
- Removed the `--experiment-eval` flag and `training.experiment_eval_*` keys; grep-clean confirmed.
- Committed the restructure; the pre-existing node-110 run that used the old flag was killed and relaunched with `--eval-config experiment_on.yaml` for provenance.
