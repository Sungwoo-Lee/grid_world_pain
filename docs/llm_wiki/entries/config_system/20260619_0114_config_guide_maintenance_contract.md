# CONFIG_GUIDE + Maintenance Contract (agents bound to read/update)

## Key conclusion
The durable answer to "how do we keep the config system documented as it keeps changing" is a layered doc set + an enforced contract. A new collaborator-facing `docs/environment/CONFIG_GUIDE.md` (placed in the VISIBLE env reference series, because `docs/develop/active/meta/` was judged not visible to collaborators) explains the v3.0 system conceptually. Its load-bearing **Maintenance Contract** binds any config-schema change to, in the SAME change: update `default.yaml` + its comment, update the guide and `02_config_schema.md`, add/extend a test, and keep the parity gate green. Critically, the contract is ENFORCED by wiring it into the five config-caring agent profiles, not by relying on memory — so every future session that touches configs via those agents is instructed to read-first and update-on-change.

## Evidence, measurements, facts
- **Doc layering (each answers one question)**: per-key "what does this knob do" stays in `default.yaml` inline comments; system/workflow lives in `CONFIG_GUIDE.md`; the exhaustive key-by-key reference stays in `02_config_schema.md`; `config_loader.py` is the source of truth the guide points to (so the guide stays conceptual and rots slowly).
- **Agents bound** (exact obligation in each `.claude/agents/*.md`): `env-config-auditor` + `experiment-designer` (PRIMARY — read before ANY config work; update guide + `02_config_schema.md` on schema/system change); `developer` + `senior-developer` + `code-reviewer` (SECONDARY — read when touching `config_loader.py`/`EnvParams`/`configs/`; update in the same change).
- **Cross-links**: one-line pointer in project `CLAUDE.md` (kept minimal per the standing rule); a hub link in `ENVIRONMENT_SUMMARY.md`; a "v3.0 updates" banner in `02_config_schema.md` (and its stale "entities not used yet" line corrected).
- `docs/environment/` is a narrative series OUTSIDE the develop frontmatter contract — no YAML frontmatter added; matched the existing header style.
- Commits: `3a89d0d` (guide), `4c9604f` (agent wiring).

## Decisions and actions
- **Pattern**: bind process/maintenance contracts into agent profiles (the per-invocation instruction surface) rather than into memory or CLAUDE.md, when the goal is enforcement across sessions for a specific role.
- Generalises the documentation-framing-policy promotion idea (a rule pushed to every doc-producing surface) to a maintenance contract pushed to every config-touching agent.
