# Plan review — Modulation Site Refactor (uniform FiLM at selectable sites)

## Verdict

**SOUND WITH CONCERNS — one Critical text correction required before approval.** The plan proposes making the neuromodulator (the small second network that re-tunes the main policy network) act through one uniform operation — multiply-and-add on neuron activations (FiLM) — at four switchable places, instead of today's four different mechanisms. The engineering design is well-verified: its strongest check (bit-identical outputs and parameter trees against fixtures captured *before* any code changes) is genuinely capable of failing and does not share a code path with what it tests, the 12-config migration inventory is exact, and the claimed removal of a known initialisation confound checks out in the code.

The Critical finding is not about the code plan but about a factual claim the plan inherits: it states that this project's reward does not depend on injury, so the published precedent (PAPL) for modulating the critic would not license our case. **That claim is false.** The live reward is the step-to-step reduction in homeostatic drive, and the drive is the distance of `(satiation, injury)` from the setpoint — injury is literally in the reward. The source document was already corrected (commit `c36a6355`); the plan still carries the stale version in two places and explicitly instructs the future experiment write-up to include the false caveat. That instruction, followed, would embed a wrong scientific claim in the paper chain — it must be rewritten before the plan is approved.

Severity legend — 🔴 Critical = fix before going further · 🟡 Moderate = likely costs a re-run · 🟢 Low = cosmetic · ❓ Open = an assumption nobody has verified yet.

## Assumption register

- ❓ `nnx.Rngs` draw-count per module is stable across the change — **verified structurally** for this Flax version: `nnx.Linear` consumes exactly two draws (kernel + bias keys, even with a constant `bias_init`), `nnx.Param(jnp.zeros(...))` consumes none, and the legacy-equivalent setting constructs identical modules in identical order (new heads sit strictly after `head_action`; the modulator is constructed last in `ActorCriticRNN.__init__` at `recurrent_ppo_network.py:264-288`, after all task-network parts). Holds as long as the Flax version does not change mid-change.
- ❓ No in-flight NMN training run will be resumed across the refactor boundary from a *copied saved config* rather than the migrated file under `configs/models/` (launch scripts pass repo-config paths, so the normal path is safe).
- Verified: `temp_clip` readers outside `src/` are only `save_snapshot.py:56` (already broken pre-change, fails loudly either way) and comments in `train_command-agent.sh`. No analysis tooling reads it.
