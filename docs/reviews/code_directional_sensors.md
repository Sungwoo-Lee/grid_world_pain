## Verdict (plain-language entry point)

This change teaches the simulated animal's senses about *direction*: smell is now sampled at a small diamond of grid cells around the agent instead of only at its own cell, and vision can optionally be blurred (distance becomes vague while direction stays sharp), capped at "present/absent" per cell, and blocked by entities standing in the line of sight. Everything ships switched off, and the claim is that with the switches off the agent's observations are bit-for-bit identical to before the change.

**The core claims hold.** I re-verified them independently rather than re-reading the assertions: the off-path really is bit-identical on the pinned CPU backend (the stored pre-change fixture test passes); sweeping the five continuous knobs (blur scale, blur anisotropy, blur floor, occlusion cone, occlusion strength) really does *not* trigger an XLA recompile of the environment step, while flipping the mode/range/enable switches really does (I counted compile events directly); the two copies of the 23-field curriculum "modality fingerprint" are token-for-token identical (verified by AST comparison, not by eye); and the occlusion geometry survives every edge case I attacked (an entity versus itself, entities on the agent's cell, two entities in the same cell, mutual-occlusion cycles — none misbehave).

**Two moderate problems.** First, the three blur knobs are read from config with **no range validation**, unlike the occlusion knobs two lines up: a config with `visual_blur_sigma_floor: 0.0` loads silently and produces an **all-NaN visual observation** (reproduced empirically) — and because these values are traced, load time is the *only* place a check can live. Second, the new fingerprint includes one entry per entity, so two curriculum stages that differ only in *entity count* — a historically common pattern (food-only stage → full-task stage) — now refuse to start training even when no entity uses any of the new features. The active five-stage curriculum is unaffected (verified: equal counts), but the next count-varying curriculum will hit a confusing startup failure.

**Verdict: WARNINGS** — no 🔴 blockers; 2 🟡 findings worth fixing before the next sweep or curriculum, plus low-severity notes.

## What was attacked and held (verified good)

- **Off-path bit-parity.** `tests/env/test_directional_sensors.py` compares against a fixture captured from the *pre-change* code (non-circular by construction; the fixture file exists and the test runs — 23/23 pass, 0 skips). The parity reasoning is also sound analytically: the activity mask moving from `all_props` onto `W` (`sensor.py:357`) multiplies by exact `0.0`/`1.0` values, which is exact in IEEE float; the always-on `_visual_mask_gate` contributes exact `×1.0` when no entity is masked; the matmul sees identical products in identical order. The `clamp` branch (`sensor.py:364-368`) sits **before** the background add and before out-of-bounds zeroing — correct placement (background channels keep their value, OOB cells still end exactly 0), and it is never traced in `sum` mode, so it cannot perturb the off path.
- **On-source decay rule** (`sensor.py:19`). `1/0.5^1 == 2.0` exactly in float32 (the suite pins this in traced form). The behaviour change at `decay_power: 2.0` (on-source reading 2.0 → 4.0) is *deliberate and documented* with a dated change-log entry in `CONFIG_CRITICAL_SETTINGS.md` naming all eleven affected configs, including the active `nmn_double_return_stages` curriculum — reviewed and accepted upstream; not re-litigated here. One new theoretical inf path: `0.5^p` underflows for p ≳ 150 → `on_source = inf`; unreachable at any sane config, noted for completeness.
- **Olfactory diamond** (`sensor.py:44-62`). Static `range == 0` branch preserves the exact original expression (bit-identical vs the direct call, verified, including *under the cell-vmap at range 1* — the centre cell matches the un-vmapped call byte-for-byte on CPU, the only backend parity is claimed on). Out-of-bounds masking multiplies float32 by bool (clean promotion); int agent position + int offsets stays integer until `jnp.linalg.norm` promotes, same as pre-change. Flatten order (cell-major) matches the breakdown formula `(2r²+2r+1)·V` (`sensor.py:503-505`) — cross-checked against actual observation width for five range combinations by the suite.
- **PSF weights** (`sensor.py:187-217`). Explicit `.astype(jnp.float32)` on both position arrays kills int/float promotion surprises; `d` is floored at 1e-6 via `sqrt(max(·,1e-12))`; the co-located-entity direction uses a `jnp.where` whose *both* branches are finite (no NaN-through-where trap). At the shipped floor 0.5 everything is finite including an entity on the agent's cell (suite covers this).
- **Occlusion gate edge cases** (`sensor.py:235-255`), attacked directly: self-comparison (`cos[i,i]=1` but `nearer[i,i]` is strictly false → an entity never occludes itself); entity co-located with the agent (`u=[0,0]` → cos 0 against everything → never occluded; and it cannot *be* a blocker because `blocker` requires `d > 1e-6`); two entities in the same cell (equal distance → strict `<` → neither occludes the other, so a rock does not hide the food sharing its cell); mutual occlusion/cycles impossible (would need `d_j < d_i` and `d_i < d_j`; the gate is a single pass with no visibility recursion — a hidden blocker still blocks, which is physically right). Inactive entities can neither block (masked in `blocker`) nor be seen (activity mask on `W`). Empirically confirmed the {co-located, blocker, cellmate, behind, other-bearing} pattern gates as {1, 1, 1, 0, 1}. Two blockers in one cone do not compound attenuation (`jnp.any` then one factor) — matches the docstring.
- **Static vs traced assignment** (`state.py:266-291`) is right across the board: shape-determining `olfactory_grid_range` and the branch selectors (`visual_blur_enabled`, `visual_occlusion_enabled`, `visual_value_mode`) are `pytree_node=False`; the five continuous knobs are traced leaves; the per-entity arrays are traced leaves (correct — jnp arrays are unhashable and would break the jit cache as static aux data; their *shape* is already static). `visual_value_mode` as a Python `str` static field is safe: flax puts static fields in hashable aux data, `str` hashes and compares by value, and the trace-time `==` branch at `sensor.py:364` never sees a tracer — confirmed by the observed recompile on flip. The `_occ_cos`/`_occ_strength` inert values (1.0/0.0) when occlusion is off are genuinely never traced (static branch at `sensor.py:359`), so "never read when disabled" is accurate.
- **Recompile behaviour** verified empirically (see L5 for the missing regression test): one compile of `jax_step` for the baseline, zero additional compiles after sweeping all five continuous knobs simultaneously, one additional compile each for `visual_value_mode` and `olfactory_grid_range` changes.
- **Fingerprint duplication** (`train.py:785` vs `dreamer_srl_main.py:774`): the 23 returned expressions are **AST-identical**; only docstrings/comments differ. Both call sites run at startup on concrete params from `load_env_params` — the `tuple(int(x) …)` conversions concretise *host-side* arrays, never tracers, so there is no hidden device sync inside a jit; had someone later moved the call inside a traced region it would fail loudly (ConcretizationTypeError), not silently.
- **Sensor/breakdown/noise sync.** `get_observation_breakdown` scales the existing `"Olfaction"` entry rather than adding a modality key, so `apply_perceptual_noise` needs no config change and the per-dim broadcast picks up the new width automatically (`sensor.py:388-400`); `evaluation_core._sensor_stat_columns` is dim-driven (`olf_{i}`) and adapts. The viz path routes range>0 through the same `visual_grid` pod the visual sensor uses; all three renderers read `range`/`num_features` from the entry (checked `renderer_v2.py:509-519`, `renderer.py:681`, `grid_world.py:648`).
- **Config threading.** The 5-tuple insertion into `_load_animals`'s return (both the empty-animals branch and the populated branch) matches the single unpack site; the empty-entity branches all allocate correctly-shaped `(0,)`/`(0,V)` arrays; the pool order of `parts_pos`/`parts_active`/`parts_props`/`parts_mask`/`parts_blocks` is consistent, including the conditional animal entry. The 284 skips in `tests/env/test_backward_compat_configs.py` are **not** a regression: every config now skipping for the new mandatory keys was already skipping for pre-change mandatory keys (verified: zero configs raw-contain `injury_observable` but lack `visual_value_mode`), all `extends:`-based configs resolve through the real `load_env_config` chokepoint (185/191 load; the 6 failures are pre-existing broken `extends:` targets from an old archive move), and the 13 standalone stale continual configs were stale before this change. That said, the suite's extends-blind raw loading now exercises only ~53 of 337 configs — a pre-existing coverage limitation worth someone's attention, not this diff's fault.
- **PRNG / purity / vmap.** No new randomness, no side effects; the cell-vmap nests cleanly inside `ParallelEnv`'s env-vmap with params broadcast; nothing batches `EnvParams`; the renderer is only handed indexed states.
