# Plan review — the 16-cell neuromodulator input x site grid

> **Object reviewed**: [[NMN_INPUT_SITE_GRID]] (`docs/experiments/active/nmn_input_site_grid/NMN_INPUT_SITE_GRID.md`), with its dependencies [[MODULATION_SITE_REFACTOR]] and [[return_mode_cmp_10M]].
> **Reviewed by**: plan-reviewer · **Date**: 2026-09-07
> **Verdict**: **NOT READY** — two launch-blocking findings, both cheap; one analysis-plan Critical that must be amended before any behavioural number is read.

## Verdict (plain language)

The experiment asks which sensory channels the agent's small "re-tuning" network should read, and which parts of the main network it should re-tune, by training 16 agents (one random seed each) and comparing how long they survive plus whether their bush-hiding depends on how injured they are.

The design is unusually careful about what a one-seed screen can and cannot say, and its survival-side reasoning checks out against the source data. It is not ready to launch today for two mechanical reasons: the code that lets the modulator read a *subset* of the senses (refactor Part B) does not exist in the tree yet, so ten of the sixteen agents cannot be configured — and launching the other six first would leave them un-analysable once Part B lands; and the working tree is 633 uncommitted lines, so no run launched now could be tied to a commit. Both are fixed by finishing and committing the code before launch.

The third problem is scientific. The headline behavioural prediction — that a modulated agent will flip the sign of "cover use while moving" from negative toward zero — cites a reference band that measures a different quantity than the one it defines, and the quantity it defines is itself subject to the same freeze-to-heal artefact the design says it escapes. It needs a motion-based measure (rate of *entering* cover) before it is a test of "travels to cover when hurt".

Severity legend: 🔴 Critical = fix before going further · 🟡 Moderate = likely costs a re-run · 🟢 Low = cosmetic · ❓ Open = an assumption nobody has verified yet.

## Explicit answers to the caller's questions

- **`.get('percept_add_bias_init', 0.0)` at `recurrent_ppo_network.py:361`** — confirmed present in the working tree. Every modulated config sets the key explicitly to 0.0 (req. 3), so the fallback is never exercised; it cannot affect these arms. Still a registry item for `bug-curator`.
- **Second path for shared settings to shift** — finding 2. Beyond the withdrawn Fix 1 (verified: `c83447a0` marks it withdrawn; the trainer's `MC` branch is untouched by `78a46b61` and by the dirty tree), the live paths are: the dirty tree itself; Fix 2 (`lr_critic`/`lr_modulator` wiring, still planned) landing between a first launch and a §5 relaunch; and the shared `configs/train/{default,recurrent_ppo}.yaml` / `configs/environment/default.yaml` being edited by a parallel session mid-wave. Pinning one SHA and launching in one wave closes all three.
- **Manifest reconstructibility** — tags are unique and collision-free, each row maps to one config path; add the SHA column. Note the known stale-copy trap (`KNOWN_BUGS` row "saved config carries a stale second copy of seed/episodes"): verify seed/episodes from the **top-level** keys of `models/config.yaml`, not the nested `training:` block.
- **Indistinguishable cells** — none. Each arm differs from every other by a `sites` or `input_sensors` value that is visible in its saved config and by the presence/absence of the `modulator/gamma_<site>_*` series (§4.3).

## Cost of being wrong

If findings 1–2 are ignored: ~200 GPU-hours produce runs that cannot be re-evaluated offline or reconstructed from a commit, so the behavioural half of the experiment (the half the thesis rests on) is lost and the survival half is un-auditable. If finding 3 is ignored: the runs are fine, but the headline behavioural verdict is read against a mis-sourced null and could report "context-dependent hiding" or its absence for an agent that merely froze more or less — a wrong claim in the paper, not a wasted day.

## Exit condition for NOT READY → SOUND WITH CONCERNS

Part B merged and committed; SHA recorded in the manifest; all 15 modulated configs carry `input_sensors`; §4.2 amended to a motion-based headline measure with its null computed on the existing MC seeds; findings 4 and 5 fixed in the doc. Findings 6–9 are the caller's call.
