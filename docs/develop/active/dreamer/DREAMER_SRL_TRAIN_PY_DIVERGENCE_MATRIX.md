## Context

The project currently has **two separate training entry points**: `train.py` at the repo root (RecurrentPPO, DQN, DRQN, plain PPO) and `src/algorithms/dreamer_srl/dreamer_srl_main.py` (the live Dreamer world-model agent). Both do the same jobs — parse a command line, layer YAML config files, build the environment, start WandB, run a training loop, save checkpoints, run evaluations — but they do many of those jobs **differently**, because the Dreamer entry point was ported from the upstream sheeprl codebase and grew its own conventions. The user has decided to merge them: `train.py` becomes the single entry point, delegating to Dreamer's existing training loop unchanged.

This document is the full inventory of **every place the two entry points do the same job differently**, produced by reading both files end-to-end (train.py @ 2,445 lines, dreamer_srl_main.py @ 2,112 lines, branch `v3.0`, HEAD `385b92f` + the committed `8afb961` rename). Each row carries a verdict: **unify-to-train.py** (train.py's convention wins on the integrated path), **keep-dreamer** (Dreamer's mechanics are preserved inside the delegated loop), or **needs-decision** (resolved in the plan doc; the chosen resolution is noted here). The integration plan's compatibility table is derived from the unify-to-train.py rows.

**Line-number baseline (rev 4)**: dreamer_srl_main.py **2,425 lines**, train.py **2,523 lines** (post `e834ec1`/`ad8929a`). Key re-verified anchors: dreamer seam waist :574, pre-seam locals :514-515, num_envs :583, budget block :594-618 (`env_max_steps` :593 stays), WandB labels :944/:980, `np.random.seed`/`PRNGKey` :733-734, eval seed via `testing.seed` :712, resume block :1369+/:1437+; train.py peek :508, stage-0 alias :564, propagation loop :556-561, algorithm read :650, probe gate :669, signals :449-450. Rev-1/2 rows citing older numbers are off by +1 (train.py, post-`fff6055` rows) or up to ~+115/+300 (dreamer_srl_main.py §1-§5 / late-file rows); the anchors above are authoritative.

## 7. Extraction-seam verdict

**The seam is clean after one mechanical, behavior-preserving refactor — re-verified at the rev-4 baseline (2,425 lines).** `main()` in dreamer_srl_main.py is a monolith, but its data flow has a natural waist at line ~574: everything above it produces exactly four values — `env_cfg`, `agent_cfg`, `schedule` (or None), and the CLI namespace — and everything below it consumes only those four, plus the scalar `args.*` fields (`seed, num_envs*, episodes*, total_timesteps*, results_dir, wandb_project, wandb_name, no_wandb, quiet, debug, buffer_device, legacy_grad_loop, **load_checkpoint, load_episode** (rev 4 — resume block §12b :1369+ is below the seam), log_interval, env_config, agent_config, configs_dir, continual_schedule`; * = resolved pre-seam), **plus two pre-seam locals: `import os as _os` (:514) and `_project_root` (:515), both consumed by the results-dir/dump block — re-imported/re-derived inside the extracted function**. Rev 4 note: the two eval passes no longer consume `args.seed` — they read `eval_seed` from the `testing.seed` config key (:712), so the seed sweep is 4 sites (:733, :734, :956, :1585). No other globals, no module state, no `args` escape into the loop.

Extraction: a frozen `DreamerRunSpec` dataclass carrying those fields + a `run_dreamer_training(spec, env_cfg, agent_cfg, schedule)` function containing lines ~574-2425 **in the same module** (num_envs/budget resolution — precisely line 583 and lines 594–618, with the `env_max_steps` read at 593 retained and the env-step-mode WARNING moving to both callers — moves to the callers; that is exactly the part being unified). The `ad8929a` retention guard (:667-705) and the `e834ec1` resume + stage-rebuild blocks (:1369+, :1437+) sit inside the extracted body and delegate unchanged. Same-module extraction keeps every existing test import valid (`_advance_episode_counters`, `_eval_scalar_prefix`, `_reset_terminal_step_data`, `ContinualSchedule`, `_build_continual_schedule`, `_load_stage_env_cfg`, `Player`, `main` — plus the new `test_continual_resume_rebuild.py`, which drives the resume path and is retargeted at the seam alongside `test_eval_telemetry_wandb.py`).
