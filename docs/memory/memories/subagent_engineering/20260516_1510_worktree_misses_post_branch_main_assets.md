# Worktree misses lit-review assets that landed on main after branching

## Recovery cheat-sheet (top of file)

```bash
# Detect the gap
ls docs/project/references/<topic>/ ; ls /media/nas01/projects/Interoceptive-AI/grid_world_pain/docs/project/references/<topic>/

# Sync needed assets
cp -r /media/nas01/projects/Interoceptive-AI/grid_world_pain/docs/project/references/<topic>/<missing-files> docs/project/references/<topic>/

# Spawn agents AFTER the sync; they will read from the worktree path and see the synced files.
```

## Key conclusion

In long-running planning sessions, the worktree is created from origin/main at session start, but the user's main checkout continues to land new content on the active branch (v1.4). **Sub-agents running in the worktree are blind to assets that landed on main AFTER the worktree branched.** This session hit it twice — once when the neuromod-corpus lit-review was needed (master review + 40 per-paper reviews on v1.4), once when the FiLM-corpus lit-review was needed (master + synthesis + 23 per-paper reviews + 22 source PDFs on v1.4). Recovery in both cases: `cp -r` the missing assets from main into the worktree before spawning the agents that need them.

## Evidence, measurements, facts

- **Symptom**: an agent claimed "no master lit-review or per-paper reviews exist" while I had just seen them on v1.4 via `ls` of the main path.
- **Cause**: worktree branched from `origin/main` (which was behind v1.4 at the time). The neuromod-corpus and FiLM-corpus lit-review work landed on v1.4 in parallel sessions after the worktree was created.
- **Two specific recoveries this session**:
  - Neuromod corpus (~40 PDFs + master + synthesis + 40 reviews): synced before spawning the 4 professor agents in the v3-round symposium. The literature-curator built the predictions synthesis on top of this synced state.
  - FiLM corpus (1 PDF → 23 PDFs + master + synthesis + 23 reviews): synced before spawning the literature-curator for the FiLM/neuromod integration synthesis.
- **Sync command**: `cp -r /media/nas01/projects/Interoceptive-AI/grid_world_pain/docs/project/references/<topic>/<missing> docs/project/references/<topic>/`. The files are then untracked in the worktree but visible to agents.
- **Distinct from other worktree insights**:
  - [[20260513_2310_orphan_memory_branch_rewrite]] — about synthetic memory-index conflicts during propagation (different mechanism).
  - [[20260516_1435_worktree_baseref_and_propagation]] — about EnterWorktree base-ref + post-work propagation pattern (different timing).
  - This insight is about the **pre-spawn sync gap**: the worktree is missing assets that exist on main *now*, before any agents have run.

## Decisions and actions

- **Pre-spawn check pattern**: before spawning agents that depend on a lit-review corpus, list both the worktree path and the main-checkout path. If main has more files, `cp -r` the delta first.
- This was applied twice this session; both recoveries worked cleanly without rework.
- A future automation: a `scripts/sync_main_assets.sh <subtree>` helper could automate the diff + copy. Not built yet.

## Open questions and follow-ups

- Whether this pattern should be folded into the `EnterWorktree` skill itself (auto-sync on enter) is open. Trade-off: simpler agent prompts vs unexpected file changes.
- Whether `git fetch` + `git merge origin/v1.4 --ff-only` in the worktree would solve it more cleanly than `cp -r` (which leaves files untracked) is open — `cp -r` is simpler but doesn't track the assets in the worktree's branch history.
