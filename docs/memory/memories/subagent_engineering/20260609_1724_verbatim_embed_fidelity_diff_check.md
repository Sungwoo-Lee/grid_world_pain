# Verbatim source embedding into docs needs a programmatic diff-vs-source gate

## Key conclusion
When you fan out parallel sub-agents to embed verbatim source code into documentation (each captioned with a `src/file.py:Lstart-Lend` anchor), the agents reliably introduce silent transcription artifacts — even when they self-report "pasted byte-for-byte" and "verified character-by-character." A programmatic checker that re-extracts every fenced code block, parses its caption, and diffs it against the actual source lines is **mandatory**, not optional. In this session it caught real defects on 15 of 80 blocks that all five reporting agents had claimed were exact.

## Evidence, measurements, facts
- Task: converted all 14 `docs/environment/` reference docs into teaching docs, embedding every in-scope function's full body verbatim with primer-linked `> API notes` callouts. ~80 captioned code blocks across the docs.
- Artifact classes observed:
  - **Mojibake** — box-drawing `─` (U+2500, bytes `e2 94 80`) written as double-encoded UTF-8 (`c3 a2 c2 94 c2 80`), rendering as `â──`. 4 lines in `02_config_schema.md`.
  - **Escaped apostrophes** — `Let\'s` / `agent\'s` (30 occurrences in `09_sensors_and_observation.md`), from a Python string that was never unescaped.
  - **Unicode glyph substitution** — `Δ`→`delta`, `→`→`—`, `—`→`--` (doc 12 renderer; changes string-literal content).
  - **Whitespace normalization** — collapsed column-alignment spaces (`arrows        =` → `arrows =`).
  - **Injected annotation** — an agent added `# config_loader.py:944-955` inline inside a "verbatim" block (doc 10).
- The corruption concentrated in agents that fell back to the conda-Python write path (`/.../bin/python` writing the file) because the bg-session isolation guard blocked their Edit/Write — see [[20260528_1647_bg_isolation_subagent_bypass]]. That write path is where the non-ASCII double-encoding entered.
- Checker design that worked: regex the `Source: path:S-E` caption (handle en-dash AND hyphen, caption above OR below the fence), pull `src[S-1:E]`, compare line-lists; skip blocks containing an explicit `# ... (omitted ...)` elision marker; length-guard auto-fixes (only re-embed when block span is within +/-2 of caption span, so umbrella/partial captions are never clobbered).
- After fixes + length-guarded auto-re-embed of non-elided blocks: 74/80 byte-exact; the 6 residuals were cosmetic glyph/whitespace drift inside deliberately-elided matplotlib blocks (doc 12), which were left and disclosed.

## Decisions and actions
- Standing rule for verbatim-embed tasks: after the agents finish, run a diff-vs-source checker over every captioned block before declaring done. Treat agent self-reports of fidelity as unverified.
- Prefer fixing programmatically: for non-elided blocks, re-embed `src[S-1:E]` exactly (length-guarded) rather than hand-patching glyphs.
- For the mojibake class specifically, the per-line `s.encode('latin-1').decode('utf-8')` round-trip (ftfy-style) safely no-ops on already-correct lines and fixes double-encoded ones.
