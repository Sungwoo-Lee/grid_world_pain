# v8 noise-index-mismatch bug is NOT present in current code

## Key conclusion
The `NMN_PERFORMANCE_DIAGNOSIS_v8.md` doc flags a "noise-config index-mismatch bug" in §2.3 / §6.3 P0 — a concern that modalities receive each other's σ values, which would invalidate every per-modality interpretation in v8 and any noise-heterogeneity follow-up. A direct code re-read (done by the experiment-designer and re-verified by env-config-auditor on 2026-05-08) shows that `config_loader.py:432–471` builds `noise_modality_order` by iterating YAML keys through `_YAML_KEY_TO_SENSOR_NAME`, and `sensor.py:222–235` looks up σ via `modality_map = {name: i for ...}` — the mapping is name-keyed throughout. There is no positional assumption anywhere in the path that could route P5's σ=0.6 olfaction onto a different modality. The bug is gone (or was never present in this code path).

## Evidence, measurements, facts
- `src/environment/config_loader.py:432–471` — name-keyed construction of `noise_modality_order` via `_YAML_KEY_TO_SENSOR_NAME` mapping.
- `src/environment/sensor.py:222–235` — `modality_map = {name: i for i, name in enumerate(params.noise_modality_order)}`; `idx = modality_map[sensor_name]`. Pure name lookup at lookup site.
- Verified independently by experiment-designer (during the P4 follow-up sweep design) and env-config-auditor (during pre-flight audit). Two-pass agreement.
- Sweep configs `configs/experiment/nmn_noise_heterogeneity/p{1..5}_*.yaml` rely on this — if the bug were live, the heterogeneity gradient would be destroyed (P5's σ=0.6 olfaction would land on a different modality than intended).

## Decisions and actions
- The 10-cell noise-heterogeneity sweep launched 2026-05-07/08 used Profile P1 byte-identical to v8's `01-interoNocicept_noise.yaml` and 4 progressively more heterogeneous profiles (R = 2.0 → 18.0). Bug-handling decision (a) was selected: note in confounds, no code fix needed.
- v8's relative comparisons (FiLM ≤ Unmod across all grouping sizes for both MC and GAE) remain valid. Absolute σ values reported in v8 §2.2 are also correct as nominal.
- Future readers of v8 should treat the §2.3 / §6.3 P0 bug warning as resolved.
