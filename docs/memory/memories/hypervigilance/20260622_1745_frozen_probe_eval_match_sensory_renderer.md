# Frozen-agent probe eval: match training sensory params + use the canonical renderer

## Key conclusion
When you drop a frozen training checkpoint into a behavior-probe env and render an eval video, two things must match the production pipeline or the result is invalid: (1) the probe config's **sensory params — especially `decay_power` (olfactory distance discounting) — must equal the value the model TRAINED with**, otherwise the olfactory channel is off-distribution even though the observation dimension still matches; (2) the **canonical eval renderer is `renderer.py::render_jax_state`** (driven by `scripts/render_recordings.py` over `.rec.gz` recordings), NOT `renderer_v2.py::render_jax_state_v2`, which is an unused experimental dashboard skin.

## Evidence, measurements, facts
- hg10 trained with `decay_power: 1.0`; the v3.0 `environment/default` base uses `decay_power: 2.0`. Probe configs that `extends: environment/default` inherit 2.0 → had to override `sensory.decay_power: 1.0` to match hg10. Obs stays 27 either way (decay_power changes values, not dims) — so the mismatch is silent.
- Canonical pipeline: `scripts/render_recordings.py` imports `render_jax_state` + `save_jax_video` from `src/environment/renderer.py`; `src/utils/eval_recording.py` says "keep in lockstep with renderer.py". `renderer_v2.py` appears only in the autogenerated SOURCES.txt — unused in production.
- Eval command shape: `eval_rollout.py --config <env.yaml> --checkpoint <run>/models/<step> --record` (omit `--agent_config` → it auto-loads the agent architecture from the checkpoint's saved `config.yaml`) → `.rec.gz` → `render_recordings.py <recordings_dir>`.

## Decisions and actions
- hg10-matched hypervigilance configs set `sensory.decay_power: 1.0` and copy hg10's predator/rabbit smell vectors.
- Use `render_recordings.py` (renderer.py) for all probe eval videos; abandoned the earlier renderer_v2 previews.
