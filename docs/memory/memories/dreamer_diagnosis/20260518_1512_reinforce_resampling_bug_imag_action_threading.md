# REINFORCE re-sampling at loss-time was the v1 H1 root cause

## Key conclusion
v1's policy-learning failure (ep_len 103.8, random floor) traced to a one-line bug in the actor objective: `actor_module(sg_latents[h], actor_keys[h])` was called inside the loss to recover `log_prob` for the REINFORCE estimator, which silently drew a **fresh** Gumbel sample for the discrete action at every step `h`. The advantage at step `h` was computed from the action that the imagination roll-out had actually taken (call it action_OLD), but the `log_prob` was being computed for the freshly-sampled action_NEW. Pairing `log_prob(action_NEW) × advantage(action_OLD)` yields a gradient that is essentially noise; the actor cannot learn. The fix is to thread the imagined action through explicitly — `imag_outputs["imagined_actions"]` is computed once during the world-model imagination roll-out, then used at loss-time via `log_prob_h = sum(sg(imagined_actions[h]) * log_softmax(logits_h), axis=-1)`. The bug is the dominant single contributor to the v1→v2 ep_len jump 103.8 → 501.

## Evidence, measurements, facts
- v1 ep_len_avg (parity, food-only): 103.8 ≈ random floor.
- v2 ep_len_avg after fix (same task, same seeds, same env): 501 — see [[20260518_1511_dreamer_srl_v2_parity_pass_outperform]].
- Bit-identity grad parity test added in v2-CP9 (`tests/algorithms/dreamer_srl/test_grad_parity.py`) catches this class of bug deterministically — would have flagged v1 at code-review time.
- Bug pattern: `pi.log_prob(action)` where `action` is freshly resampled from a stochastic distribution. The symptom is "loss is finite, gradient is finite, but policy never learns".
- Plan-only review (which passed v1) cannot catch this — it requires either grad-parity testing or a sub-agent reading the call-graph and asking "does this action have the same identity as the one whose advantage I'm pairing with?".
- The same pattern (sample-then-recompute-log-prob) is a common gotcha in any imagination-based actor: DreamerV3, PlaNet, world-model SAC. Not specific to JAX.

## Decisions and actions
- v2 master recipe carries the explicit action-threading pattern in `src/algorithms/dreamer_srl/train.py:compute_actor_objective`. Future rebuilds inherit it.
- Grad-parity bit-identity test is the canonical CI guard for this class of bug; any future imagination-based actor must add an equivalent.
- Generalisable rule for future-Claude: **"when the loss computes a log-prob, the action whose log-prob is being computed must be the same identity as the action that produced the reward / advantage being paired with it."** A re-sample at loss-time is a silent gradient-randomiser.
