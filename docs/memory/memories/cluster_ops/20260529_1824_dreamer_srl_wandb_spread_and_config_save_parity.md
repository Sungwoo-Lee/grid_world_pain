# dreamer-srl WandB-config spread + dual config-save parity with rPPO

## Key conclusion

`dreamer_srl_main.py` was passing the entire agent YAML tree to WandB as `wandb_config["agent"] = agent_config_dict`, which made the UI filter `agent.algorithm = DreamerV3` appear broken — the tree contained both a top-level `algorithm` key AND a nested `agent.algorithm` key (`agent.agent.algorithm`), and the UI tripped on the duplicate. rPPO's `train.py` solves the same problem with the spread pattern `**config.to_dict()`, which lands the agent YAML's `agent:` block directly at `wandb.config.agent` (clean `{algorithm: "RecurrentPPO"}` dict). Replacing the dict-key wrap with the spread pattern brought dreamer-srl to parity. Separately, dreamer-srl was not saving any source YAML to `<results_dir>/models/` (rPPO saves `config.yaml`); added `env_config.yaml` + `agent_config.yaml` as TWO separate files so the `--env-config` / `--agent-config` CLI provenance is preserved.

## Evidence, measurements, facts

- Pre-fix structure (verified by WandB API): `wandb.config.agent = {algorithm: "DreamerV3", agent: {algorithm: "DreamerV3"}, algo: {...}, buffer: {...}, env: {...}, training: {...}}` — doubly nested.
- Post-fix structure (smoke run `mo1pkvm5`, 200 env-steps, num_envs=1): `wandb.config["agent"] == {"algorithm": "DreamerV3"}` — clean, single level.
- Top-level keys after spread now include `agent, algo, buffer, training, env, environment, body, sensory, perceptual_noise, behavior_measures, visualization, ...` — all data preserved, just one nesting level shallower.
- Saved files: `env_config.yaml` (15001 B) + `agent_config.yaml` (1623 B) at `<results_dir>/models/` — verified well-formed YAML.
- rPPO reference paths: `train.py:561-566` for config save, `train.py:599-617` for spread pattern.
- Fix landed at `src/algorithms/dreamer_srl/dreamer_srl_main.py:386-419` (spread) + after line 467 (save). Commit `2356c33`.

## Decisions and actions

- Adopted the **spread** pattern (env spread first, agent spread second; agent wins on collision) as the canonical WandB-config build for dreamer-srl. Now matches rPPO so cross-algorithm filters work identically.
- Adopted **two-file save** (`env_config.yaml` + `agent_config.yaml`) instead of merged single file, to preserve the dual-CLI provenance — a reader can re-launch with the exact same `--env-config <path>` and `--agent-config <path>` from the saved files.
- Trade-off (logged for downstream consumers): old saved WandB filter views querying `agent.algo.gamma` / `agent.buffer.size` / `env.environment.height` will not match post-fix runs. New paths are `algo.gamma` / `buffer.size` / `environment.height`. The always-top-level scalar `algorithm = "DreamerV3"` works in both layouts.
- All 4 in-flight `_log2k` cells (w9as1qe3, x0ahp61j, jx3obafg, h7aa37na — launched 2026-05-29 02:09 KST) carry the post-fix config; old-layout cells (pre-`2356c33`) have the doubly-nested layout.
