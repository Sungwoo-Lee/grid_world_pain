# --total-steps silently disables episode termination; Dreamer resume path now exists

## Key conclusion

Two operational facts future launches must know. (1) Dreamer's while-loop is dual-mode: `--episodes` (or config training.episodes) gives episode-based termination; passing `--total-steps`/`--total-timesteps` SILENTLY switches to an env-step cap — dsrl_b04_M_128env_n114 "stopped mysteriously" because it completed exactly its 50M-step budget (390,625 iterations x 128 envs; final banner + losses printed cleanly). WandB showed "crashed" only because its background uploader thread had died ~18h earlier ("Fatal error while uploading data" — trainer unaffected; local wandb/ dir kept growing; `wandb sync` recovers). Fix commit `166f261`: configs/train/dreamer_srl.yaml now carries episodes: 100000000 (rPPO convention) and the driver prints a loud WARNING when --total-steps disables episode mode. (2) dreamer_srl previously had NO resume path (checkpoint.py's load_checkpoint was never imported; docstring said "write-only until a future plan adds restore"). Implemented: --load-checkpoint/--load-episode via restore_dreamer_training_state() mirroring rPPO's fatal-on-failure restore-to-target pattern; save_checkpoint now stores Adam optimizer state (old checkpoints auto-detected via checkpoint_has_optimizers → network-only fallback with warning); the replay buffer is NOT checkpointed, so gradients are held max(learning_starts, seq_len+1) iterations while the RESTORED policy refills it (otherwise the first train step samples an empty buffer).

## Evidence, measurements, facts

- Resume verified against the real b04 checkpoint (ep 380002): 92 param leaves restored; WM loss resumed at 1.66 ≈ b04's final 1.77, vs fresh-init ~2.79 — weights genuinely loaded. 7/7 checkpoint tests.
- Downstream gotcha: optimizer-bearing checkpoints break StandardRestore model-only targets — eval consumers need PyTreeRestore(partial_restore=True) (fixed in eval_rollout.py, visualize_dream.py, dreamer_srl_probe_eval.py commit `a0d209d`).
- MomentsState is flax.struct.dataclass: rebuild with .replace(), not ._replace() (first resume attempt crashed on this inside the jitted step).

## Decisions and actions

- All Dreamer launches use --episodes; never --total-steps except as a flagged one-off.
