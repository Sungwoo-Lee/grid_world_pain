# Eval sweep is CPU-bound (multithreaded XLA compile), not NAS-bound

## Key conclusion
The behaviour-probe eval sweep's earlier "the shared NAS saturates when you fan reads across nodes" diagnosis was WRONG. The sweep is **CPU-bound**: each `eval_rollout.py` process spends ~13 s in JAX import + XLA compile, and that compile is **multithreaded and sizes its threadpools to the whole core count**. So a handful of concurrent processes oversubscribe the CPU (measured: 16 procs -> load 100 on a 20-core node). The infamous load-137 freeze with un-killable processes was that thread oversubscription **amplified by stacked workers I could not kill from a sandboxed container** (each failed relaunch left the old worker running) - not NAS I/O. Parallel checkpoint *reads* off the NAS were never the bottleneck.

## Evidence, measurements, facts
- Measured on a 20-core node: single eval cold = 14.7 s; NPAR=16 no-cache no-cap = 3.43 s/eval at **load 100**; NPAR=16 warm cache = 1.92 s/eval still load 99; **NPAR=18 warm cache + 1-thread cap = 0.66 s/eval at load 29**.
- Bare `import jax` + tiny op = ~2.1 s; full single eval = 14.7 s -> ~12-13 s is fixed per-process import+compile.
- Fix knobs: (1) persistent XLA compile cache (`JAX_COMPILATION_CACHE_DIR` + `JAX_PERSISTENT_CACHE_MIN_ENTRY_SIZE_BYTES=0` + `..._MIN_COMPILE_TIME_SECS=0`) - the compiled program depends only on SHAPE, identical across a model's checkpoints, so eval #2..N skip the ~7 s compile; (2) 1-thread cap per process (`OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1`, `XLA_FLAGS="--xla_cpu_multi_thread_eigen=false intra_op_parallelism_threads=1"`); (3) NPAR ~= core count.
- With the fix, fan-out across nodes 101-105 distributes fine (each thread-capped node sits at load ~29) - the opposite of the earlier "do not fan out" advice.
- The sandbox Bash tool cannot kill the stuck processes; `kill`/`pkill` from the sandbox and even `run_command.py` to node 102 could not reach container-namespace worker processes (they drain on their own once their parent worker is dead).

## Decisions and actions
- Rewrote `docs/environment/LAB_NODE_GPU_SPEC.md` (commit 8de24a0): replaced the "NAS saturates at 150-way reads" claim with the measured CPU-bound diagnosis + the compile-cache/thread-cap/NPAR fix. Section renamed "Eval-sweep parallelism - CPU-bound, thread-cap it".
- The dwell/metrics workers (`tmp/dist_metrics_worker.sh`, `tmp/dist_dreamer_worker.sh`) bake in the thread caps + per-node compile cache + NPAR=18.
