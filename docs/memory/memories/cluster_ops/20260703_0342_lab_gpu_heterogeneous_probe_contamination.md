# Lab GPUs are heterogeneous; run_command.py is unsafe for parallel node queries (shared-log contamination)

## Key conclusion
The 14 lab nodes are NOT identical. Real inventory (direct-SSH probe 2026-06-30): RTX 2080 Ti 11GB on 101/103/104/105; RTX 3090 24GB on 106-112; RTX 4090 24GB on 102/113; RTX 6000 Ada 49GB on node 114 — and node 114 has **4 GPUs (indices 0-3)** while every other node has only 2 (0,1). A first probe wrongly concluded the cluster was homogeneous (all 2080 Ti) because it used `run_command.py` in parallel: that wrapper nohups each remote command to a single timestamped NAS log (`logs/YYYYMMDD_HHMMSS.log`) and tails it, so ~14 calls in the same second shared one log file and every per-node result showed one node's output (byte-identical rows were the tell). Correct method: query each node over DIRECT SSH with `subprocess capture_output` per node — never route a data-returning query through run_command.py. GPU assignment for a launch must (a) use only indices that exist on that node, and (b) match card to job (routine small rPPO/Dreamer -> low/mid tier; reserve 4090/Ada for heavy jobs).

## Evidence, measurements, facts
- Shipped: `scripts/lab/gpu_status.py` (direct-SSH live spec+state+processes; modes `--spec-only`/`--free`/`--nodes`), the `gpu-status` skill (use BEFORE assigning a node:GPU for any launch), and `docs/environment/LAB_NODE_GPU_SPEC.md` (per-node tier table). CLAUDE.md Project-Wide-Rules bullet points at the doc. Registered in SCRIPTS_DEPENDENCY_MAP.
- The tool immediately proved its worth: it flagged node 108's GPUs as idle — which was correct (two variant launches there had been SKIPPED because /media/nas01 was unmounted on 108).
- Two prior mistakes this fix addresses: suggesting `cuda:2` on a 2-GPU node (108), and using a high-spec card for a small job.

## Decisions and actions
- Always run `gpu_status.py`/the `gpu-status` skill before a launch; the training-runner still does its own live nvidia-smi + NAS-mount pre-flight (df | grep nas01).
- NAS-mount gotcha recurred (107 historically, 108 this session): a node can be SSH-reachable but have /media/nas01 unmounted, so logs/checkpoints silently fail — the runner correctly SKIPS such nodes.
