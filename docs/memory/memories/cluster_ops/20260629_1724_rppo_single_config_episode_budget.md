# rPPO single-config budget comes from --episodes, not --total-timesteps

## Key conclusion
For a single-config (non-continual) RecurrentPPO run, the training loop at `train.py:1183` is `while (total_episodes_completed < episodes) if episodes > 0 else (global_step < total_timesteps)`. Whenever `episodes > 0` the loop uses the EPISODE budget and `--total-timesteps` is ignored entirely (line 465 still computes total_timesteps but it is never consulted). `episodes` defaults to `config.get_mandatory('episodes')` = 100, so a run launched with only `--total-timesteps 10000000` trains 100 episodes (~45s) and prints "Training complete". The correct budget knob is `--episodes <N>` (the project convention is `--episodes 10000000` as a generous manually-stopped ceiling, matching `train_command-new.sh`). Do NOT pass `--episodes 0` to "fall through" to the step budget — that disables the conventional episode budget.

## Evidence, measurements, facts
- First launch of `rppo_basic05_randinit_n112` (WandB `k9wyijj3`) passed `--num-envs 16 --total-timesteps 10000000 --checkpoint-frequency 1000` but NO `--episodes`; it exited after ~45s having run 100 episodes (tqdm `total=100`). Defunct.
- Relaunch (WandB `ga5fkr1q`) with `--episodes 10000000` (no --total-timesteps): tqdm `total=10000000`, process stayed alive past JIT — correct.
- Source: `train.py:1183` loop condition; `train.py:458` `episodes = args.episodes if args.episodes is not None else config.get_mandatory('episodes')`; `train.py:465` total_timesteps computed but only used when episodes<=0.

## Decisions and actions
- Standing rule for training-runner: single-config rPPO launches MUST set `--episodes <N>`; treat `--total-timesteps` as inert when episodes>0.
- This is the rPPO twin of [[20260622_1747_dreamer_srl_single_config_budget_source]] (dreamer_srl reads the budget from `env_cfg.training.*`, also defaulting to an instant exit). Same failure CLASS: single-config mode has a non-obvious default budget that silently truncates the run.
