# Per-episode entity-count variance via static-max allocation + activation masks

## Key conclusion
To stop the agent overfitting to a fixed layout (it learned to roam-avoid the predator instead of
bush-diving), the env now **randomizes entity counts per episode**. JAX requires static array shapes,
so counts can't literally vary; the pattern is: allocate **count_high** slots (static size), per-episode
draw **K ~ Uniform[low, high]** and **activate K via a boolean mask**, parking the rest off-grid. The
default scene also moved to **whole-grid spawn** (collapsed from 4 quadrant entries per entity to one).
Scalar `count: N` stays fully backward-compatible (= low=high).

## Evidence, measurements, facts
- New optional config keys `count_low`/`count_high` (loader: `config_loader.py`); when only scalar
  `count` is given it behaves exactly as before -> the ~100 existing configs are untouched and parity
  stays green.
- Three activation masks gate inertness: existing `res_active` (food + hiding_predator), and NEW
  `animal_active` (predator/rabbit) + `obs_active` (rock/bush). Each must be threaded through every
  consumption site (movement, damage, sensing, collision, bush-concealment, distance metrics) so an
  inactive slot is fully inert. K-draw + masks live in `jax_reset` (`core.py`).
- Default ranges (locked): food 2-6, bush 4-10, rock 6-12, predator 1-2, **rabbit 1-2** (trimmed from
  1-3 for speed), hiding_predator 2-4; all spawn full-grid `[[1,1],[10,10]]`. `placement.mode: per_entity`
  kept (benchmark showed per_type no benefit at this entity count).
- **Two-commit parity discipline:** commit 1 (`90d687f`) lands the masking machinery with the scene
  UNCHANGED -> both parity suites stay green, proving byte-transparency; commit 2 (`7fa6183`) changes
  the default scene and regenerates EXACTLY the 2 default fixtures. Blast radius is exactly the default
  config — every other config overrides `resources`/`entities`/`obstacles`, so they are insulated.
- Final fix commit `61e0c73` (see [[20260623_0144_inactive_resource_slots_revive_respawn]]).

## Decisions and actions
- Ranges locked per the user (rabbit trimmed 3->2 to recover ~half a step-throughput regression, see
  [[20260623_0145_proxy_benchmark_contention_misestimate]]); per_entity placement; collapse quadrant
  entries to single full-grid entries.
- Same optional-range-key pattern as [[20260619_0113_configurable_initial_state_ranges]] (start_*_low/high).
- Docs updated per the Maintenance Contract (CONFIG_GUIDE §3.6 + 02_config_schema).

## Open questions and follow-ups

in-flight run is affected (all current experiment configs override the scene).
