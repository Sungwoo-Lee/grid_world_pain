# sensory.decay_power silently drifted 1.0->2.0; reverted to 1.0

## Key conclusion
The olfactory distance-discounting exponent `sensory.decay_power` (smell intensity = `1/dist^p`, formula in `src/environment/sensor.py`, cap 2.0 on the source cell) had silently drifted from the intended `1.0` to `2.0`. The change rode into commit `def81c1` (2026-02-27, "scale down the grid world environment to 10x10, simplify object and predator configurations …") whose message never mentioned olfaction/decay/smell. Every training run and every core avoidance probe since has inherited `2.0` (inverse-square, smell reaching only ~1-2 cells) instead of `1.0` (gentler, longer-range gradient the agent can follow from afar). Reverted `configs/environment/default.yaml` to `1.0`.

## Evidence, measurements, facts
- Ground truth was the SAVED config, not source: all three checked runs' `models/{config,env_config}.yaml` showed `decay_power: 2.0` (Dreamer b04_128env, rPPO b04_gae, rPPO-NMN b04_mc); all 12 core avoidance probes resolved to `2.0` too — training and eval were consistent, just at the unintended value.
- **Wrong-key-path trap**: my first resolver query `c.get("olfaction.decay_power")` returned `None` for every probe — a spurious null. The key actually lives under the `sensory` block: `sensory.decay_power`. Distrust a None before concluding "unset"; dump the real subtree.
- `git blame`/`log -L` on `configs/environment/default.yaml:192` showed the one-line `1.0`->`2.0` diff inside `def81c1`; author = the user themselves; message had no olfaction reference.
- Falloff table: at 2/3/4 cells, `1.0` gives 0.50/0.33/0.25 vs `2.0` gives 0.25/0.11/0.06.
- The intentional-override families (`explore/hypervigilance`, `olfactory_ambiguity_lindecay`) set `decay_power` explicitly (1.0) and were unaffected by the default change.

## Decisions and actions
- Reverted `configs/environment/default.yaml` `decay_power` 2.0 -> 1.0 (commit that also created the governance doc — see [[20260726_0416_critical_settings_registry_changelog_guardrail]]).
- Logged the revert AND the retro-logged 2026-02-27 silent change in the new `CONFIG_CRITICAL_SETTINGS.md` change log.
- Caveat recorded: models trained before 2026-07-26 used 2.0 — pin `sensory.decay_power: 2.0` to evaluate them faithfully; re-train under 1.0 for a clean 1.0-regime comparison.

## Open questions and follow-ups
