# Probe re-run contamination: clean the output-root or the heatmap mixes checkpoints

## Key conclusion
`scripts/eval/eval_rollout.py --output-root X` writes recordings under `X/<cfg>/models/<ckpt-step>/recordings/<ckpt-step>/`. Re-running the same sweep on a LATER checkpoint creates a NEW `models/<new-step>/` subdir next to the old one — it does not overwrite. `scripts/behavior_measures/avoidance_stats_heatmap.py` auto-detects checkpoints (when `--ckpt` is omitted) by iterating ALL `models/*` subdirs, so it aggregates the OLD and NEW checkpoints together → a contaminated heatmap (observed as 720/360 recordings and mixed stats). Always `rm -rf` the per-model output-root before re-eval.

## Evidence, measurements, facts
- Symptom: after a "clean overwrite" re-run, each variant showed `recs=720/360` and two `models/<step>/` dirs (e.g. `1300003` + `2200003`); the heatmap averaged over both.
- Root cause: eval writes are keyed by checkpoint step, and the heatmap's `recordings_for()` globs every checkpoint dir under the output-root when `--ckpt` is not passed.
- Fix applied to the runner scripts: `rm -rf "$OUTROOT"` immediately before the eval loop for each model, so each run starts from an empty output-root. After the fix, re-runs gave a clean `360/360` single-checkpoint sweep.
- Alternative (not used): pass `--ckpt <latest>` to the heatmap so it reads only one checkpoint — but the stale recordings then linger on disk.

## Decisions and actions
- All variant/NMN/noise runner scripts clear the output-root before re-eval.
- Consolidated all avoidance eval outputs under `results/eval/avoidance/{heatmaps,sweeps,videos}` with a README (housekeeping; scripts still write to top-level `avoidance_stat_<name>` by default, so a future improvement is to point their output-root at the organized folder).
